# CivicFix Deployment Guide

There are two supported ways to run CivicFix:

- **[Option A: AWS](#option-a-aws-recommended)** (recommended for real use): always on, private database with backups, deployed by GitHub Actions.
- **[Option B: Render + Vercel](#option-b-render--vercel-free-trial)**: free, good for a trial, but the free database is deleted after about 6 weeks.

Both serve the same three parts: the **API** (with photos stored in PostgreSQL), the **admin portal** for staff, and the **Android app** for citizens.

---

## Option A: AWS (recommended)

### What gets created

All in one region (default **Mumbai, `ap-south-1`**), from the templates in `infra/aws/`:

| Part | AWS service | Notes |
|---|---|---|
| API | ECS Express Mode (Fargate) | Gets its own HTTPS address `https://….ecs.<region>.on.aws`; 1–2 tasks of 0.5 vCPU / 1 GB |
| Database | RDS PostgreSQL 17, `db.t4g.micro` | Private (no internet access), encrypted, daily backups, deletion protection |
| Secrets | Secrets Manager | Database password and login-token key, generated by AWS |
| Admin portal | S3 + CloudFront | HTTPS address `https://….cloudfront.net` |
| Container images | ECR | Last 20 kept |

**Cost:** roughly USD 50–70 a month at low traffic, mostly the load balancer, the API task, the database and public IP addresses. New AWS accounts get free-tier credits that cover part of this. Check with the [AWS Pricing Calculator](https://calculator.aws/) and set a budget alert (Billing → Budgets) before going live.

GitHub Actions deploys using GitHub's OpenID Connect login: **no AWS access keys are created, stored or shared**.

### A1. One-time AWS setup (about 5 minutes)

1. Sign in to the AWS console as an administrator, and pick the region you want (top right; Mumbai is the default the workflows use).
2. Open **CloudFormation → Create stack → With new resources**.
3. **Upload a template file**: `infra/aws/bootstrap.yml` from this repository. Next.
4. Stack name: `civicfix-bootstrap`. Leave the parameters as they are, unless:
   - your GitHub repository has a different owner/name, or
   - the account already has a GitHub identity provider (IAM → Identity providers lists `token.actions.githubusercontent.com`): then set **CreateGitHubOidcProvider** to `false`.
5. Next, Next, tick **"I acknowledge that AWS CloudFormation might create IAM resources with custom names"**, Submit.
6. When it shows `CREATE_COMPLETE`, open the **Outputs** tab and copy **DeployRoleArn**.

This creates one IAM role that only GitHub Actions running on this repository's `main` branch can use.

### A2. Connect GitHub to AWS

GitHub → repository → **Settings → Secrets and variables → Actions → Variables → New repository variable**:

| Variable | Value |
|---|---|
| `AWS_DEPLOY_ROLE_ARN` | the DeployRoleArn from step A1 |
| `AWS_REGION` | only if you used a region other than `ap-south-1` |

Also add the four Android signing secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`) if you haven't yet; see "Build the Android app" in Option B, step 5.

### A3. Deploy

1. Merge the latest code into `main`.
2. GitHub → **Actions → Deploy to AWS → Run workflow** (keep "build and publish the Android app" ticked).
3. The first run takes about 40–60 minutes (the database alone takes 10–15). It:
   - runs the backend tests,
   - creates the database, secrets, registry and admin hosting (`civicfix-base` stack),
   - builds and pushes the API image, and starts the API (`civicfix-api` stack),
   - waits until `/health` reports the database is OK and checks login and CORS,
   - builds the admin portal for the new API address and publishes it,
   - builds the Android app for the new API address, tests that it launches, and publishes it under **Releases**.
4. The run's **Summary** page shows the API and admin portal addresses.

After this, every push to `main` that changes `backend/`, `admin/` or `infra/aws/` redeploys automatically (without rebuilding the APK). The API address stays the same, so citizens don't need a new app unless the mobile code changes; rebuild it with **Actions → Android APK → Run workflow**.

### A4. Create your admin account

The database is private, so accounts are created by a task that runs inside AWS:

1. GitHub → **Actions → AWS admin task → Run workflow**.
2. Task `create-staff`, your email and name, role `admin`. Run.
3. When it finishes, open the AWS console → **Secrets Manager** → `civicfix/staff/<your email>` → **Retrieve secret value**. That's your password. It never appears in GitHub logs.
4. Sign in at the admin portal address.

Use the same workflow with role `staff` for officers (they can update issues but not delete them). Running it again for an existing email gives that person a new password.

### A5. Check everything end to end

Same checklist as [Step 6 below](#step-6-check-everything-end-to-end), using the AWS addresses.

### Day-to-day on AWS

- **Logs:** CloudWatch → Log groups → `/civicfix/api`.
- **Backups:** RDS keeps 7 days of automatic backups (point-in-time restore). Deleting the stack keeps a final snapshot.
- **Unused photos:** **AWS admin task** → `prune-uploads (list only)`, then `prune-uploads (delete)`.
- **Bigger database or API:** set repository variable `DB_INSTANCE_CLASS` (e.g. `db.t4g.small`), or change `Cpu`/`Memory`/`MaxTasks` in `infra/aws/api.yml`, and redeploy.

### Troubleshooting AWS deploys

| Message in the failed run | Fix |
|---|---|
| `No default VPC` | VPC console → **Actions → Create default VPC**, then re-run |
| `Not authorized to perform sts:AssumeRoleWithWebIdentity` | `AWS_DEPLOY_ROLE_ARN` is wrong, the run wasn't on `main`, or the repository name in the bootstrap stack doesn't match exactly (it is case-sensitive) |
| `backup retention period exceeds the maximum available to free tier` | Set repository variable `DB_BACKUP_DAYS` to `1` and re-run |
| `Provider with url https://token.actions.githubusercontent.com already exists` (bootstrap) | Delete the failed bootstrap stack and create it again with `CreateGitHubOidcProvider` = `false` |
| API never becomes healthy | CloudWatch log group `/civicfix/api` shows the error (often the database is still being created on a first run: re-run) |

### Removing everything

Delete the `civicfix-api` stack, then `civicfix-base`. The database has deletion protection: turn it off first (RDS → civicfix-db → Modify). AWS keeps a final snapshot of it, which you can delete later. Finally delete `civicfix-bootstrap`.

## Option B: Render + Vercel (free trial)

## Step 1: API and database on Render

1. Merge the latest code into `main`.
2. In Render: **New → Blueprint**, select this repository. Render reads `render.yaml` and proposes:
   - `civicfix-api`: web service (Docker, `backend/`)
   - `civicfix-db`: PostgreSQL
3. When asked for `CORS_ORIGINS`, **leave it empty for now** (you'll set it in step 4). The API starts without it; only the admin portal is blocked until it is set.
4. Click **Apply** and wait for the deploy to finish.
5. Copy the service URL, e.g. `https://civicfix-api.onrender.com`. This is your **API URL**.
6. Open `<API URL>/health`. You should see `{"status":"ok","database":"ok"}`.

`JWT_SECRET` is generated by Render, `DATABASE_URL` is wired from the database, and `DB_SYNC=true` creates all tables on start.

## Step 2: Create your admin account

Public sign-up only creates citizen accounts. Create staff/admin accounts from your computer:

1. In Render, open `civicfix-db` → **Connect** → copy the **External Database URL**.
2. Run:

```bash
cd backend
npm ci
DATABASE_URL="<External Database URL>" DATABASE_SSL=true \
  npm run create-staff -- --email you@example.com --name "Your Name" --role admin
```

The script prints a generated password once. Save it in a password manager. To choose the password yourself, set `STAFF_PASSWORD` (12+ characters) before the command. Use `--role staff` for officers who should not be able to delete issues. Running it again for an existing email resets that account's password and role.

If the connection fails with a certificate error, add `DATABASE_SSL_REJECT_UNAUTHORIZED=false`.

> The old `create-officers.js` script, which created admins with the password `password123`, has been removed. If you ever ran it against a database, change those passwords with `create-staff` or delete the accounts.

## Step 3: Admin portal on Vercel

1. Vercel → **Add New → Project** → import this repository.
2. **Root Directory:** `admin` (framework preset: Vite).
3. Environment variable:

```text
VITE_API_URL=<API URL>/api
```

   For example `https://civicfix-api.onrender.com/api`. The build fails on purpose if this is missing or does not end in `/api`, so you can't ship a portal that points at `localhost`.

4. Deploy, and copy the site URL, e.g. `https://civicfix-admin.vercel.app`. This is your **admin URL**.

## Step 4: Allow the admin portal to call the API

1. Render → `civicfix-api` → **Environment** → set:

```text
CORS_ORIGINS=<admin URL>
```

   Use the exact origin, with no trailing slash or path. Separate several with commas (e.g. a custom domain and the `.vercel.app` URL).

2. Save (Render redeploys), then sign in at `<admin URL>/login` with the account from step 2.

## Step 5: Build the Android app for citizens

The APK is built by GitHub Actions (`.github/workflows/android-apk.yml`): it builds a signed release APK, starts it on an Android emulator to check it reaches the login screen, and publishes it as a GitHub Release so citizens get a download link.

### One-time: add the signing key

Android only installs an update over an existing app if both are signed with the **same key**. Add these in GitHub → **Settings → Secrets and variables → Actions → New repository secret**:

| Secret | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | contents of `keystore.base64.txt` |
| `ANDROID_KEYSTORE_PASSWORD` | the keystore password |
| `ANDROID_KEY_ALIAS` | `civicfix` |
| `ANDROID_KEY_PASSWORD` | the keystore password (same value) |

Keep a backup of the keystore file and password somewhere safe outside GitHub. If the key is lost, people have to uninstall the app before they can install a newer build.

Optional: `GOOGLE_MAPS_API_KEY` (an Android Maps SDK key from Google Cloud) shows a map on the report screen. Without it the app shows the coordinates and an "Open in Maps" link instead.

### Build and publish

1. GitHub → **Actions → Android APK → Run workflow**.
2. **api_url:** your API URL **without** `/api`, e.g. `https://civicfix-api.onrender.com`. If you leave it empty, the app asks for the server address on first launch (people can also change it from the login screen).
3. Keep **publish** ticked and run. It takes about 25–35 minutes.
4. When it finishes, open **Releases**: the newest `CivicFix-v…-build….apk` is the file to share. Send citizens the release link, or the direct link to the `.apk`.

Citizens install it by opening the downloaded file and allowing installs from their browser/file manager when Android asks. Each new build installs over the previous one.

Pushing a git tag named `mobile-v…` (e.g. `mobile-v1.0.1`) also builds and publishes, without a built-in server address. Without the signing secrets, any published build is marked as a **test pre-release** signed with a public debug key; uninstall it before installing an official build.

Rebuild (step 5) whenever the API URL changes, if you built it in. Changes to the API or admin portal alone do not need a new APK.

## Step 6: Check everything end to end

- [ ] `<API URL>/health` → `status: ok`, `database: ok`
- [ ] Admin portal: sign in as admin; a citizen account is refused
- [ ] APK: install, register a citizen account, report an issue with a **fresh camera photo**
- [ ] The report shows in the admin dashboard with its photo
- [ ] Staff can move it to *In Progress* and *Resolved*, with a resolution photo
- [ ] The citizen sees the new status and both photos in the app
- [ ] Wait 20 minutes (the free API goes to sleep) and open the photo again; it still loads

## Limits of the free plans (read before going live)

- **Database expiry.** Render's free PostgreSQL expires 30 days after it is created and is deleted after a further 14 days, **taking all reports, accounts and photos with it**. Before then either upgrade `civicfix-db` to a paid plan in Render, or move to a provider whose free tier does not expire (e.g. Neon or Supabase): create the database there, set the API's `DATABASE_URL` to its connection string with `DATABASE_SSL=true`, and redeploy.
- **Storage.** The free database holds 1 GB. Phone photos are typically 2–5 MB, so plan on a few hundred reports before you need a larger plan.
- **Sleep.** The free API sleeps after 15 idle minutes; the first request afterwards takes up to about a minute. The app waits up to 90 seconds and tells the user to retry if it times out.

## Maintenance

### Remove orphaned photos

Photos from rejected reports (by older versions of the API) or from deleted issues can be listed and removed with the API's database URL:

```bash
cd backend
DATABASE_URL="<External Database URL>" DATABASE_SSL=true npm run prune-uploads              # list only
DATABASE_URL="<External Database URL>" DATABASE_SSL=true npm run prune-uploads -- --delete  # remove
```

### Configuration reference

| Where | Variable | Value |
|---|---|---|
| Render (API) | `CORS_ORIGINS` | Admin portal origin(s) |
| Render (API) | `DATABASE_URL` | From `civicfix-db`, or another provider |
| Render (API) | `DATABASE_SSL` | `true` only for an external provider's URL |
| Render (API) | `API_HOST` | Leave unset; set only when using a custom domain for the API |
| Vercel (admin) | `VITE_API_URL` | `<API URL>/api` |
| GitHub Actions | `api_url` input | `<API URL>` (no `/api`) |

See [docs/environment-reference.md](docs/environment-reference.md) for every variable.

## Alternative: build with Expo EAS

`mobile/eas.json` still works if you prefer Expo's build service (needs an Expo account):

```bash
cd mobile
npx eas env:set --name EXPO_PUBLIC_API_URL --value <API URL> --environment preview --visibility plaintext
npx eas build --platform android --profile preview   # installable APK
```

## Local development

```bash
cd backend && npm ci && cp .env.example .env && npm run dev   # API on :5000
cd admin   && npm ci && cp .env.example .env && npm run dev   # VITE_API_URL=http://localhost:5000/api
cd mobile  && npm ci && cp .env.example .env && npx expo start
```

For the phone, set `EXPO_PUBLIC_API_URL` to an address the phone can reach (your computer's LAN IP), not `localhost`.

## Remaining hardening before a large public launch

1. Introduce Sequelize migrations and stop relying on `DB_SYNC`.
2. Move photos to object storage (S3/R2/GCS) once volume outgrows the database.
3. Replace the in-process rate limiter with a shared one if you run more than one API instance.
4. Add centralized logs, error tracking, uptime monitoring and tested backups.
5. Consider HttpOnly cookies instead of `localStorage` tokens for the admin portal.
