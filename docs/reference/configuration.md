# Configuration reference

Every setting CivicFix reads, where it is set, and its default. Secrets are marked 🔒 and must never be committed, printed in logs or put in a client build variable.

| Where | Set through |
|---|---|
| API | Environment variables. Locally `apps/api/.env` (copy [`apps/api/.env.example`](../../apps/api/.env.example)); on AWS the `civicfix-api` stack (from repository variables) and Secrets Manager; on Render the dashboard / `render.yaml` |
| Admin portal | `VITE_*` variables at **build** time (`apps/admin/.env`, Vercel, or the deploy workflow) |
| Android app | `EXPO_PUBLIC_*` variables at **build** time (`apps/mobile/.env` or the APK workflow) |
| GitHub Actions | Repository **variables** and **secrets** (Settings → Secrets and variables → Actions) |

## API

### Core

| Variable | Default | Description |
|---|---|---|
| `NODE_ENV` | — | `production` enables HSTS, hides 5xx details, trusts one proxy hop, disables schema sync unless `DB_SYNC=true`, and turns off the `log` email/SMS providers |
| `PORT` | `5000` | HTTP port |
| `JWT_SECRET` 🔒 | — (**required**) | Signs access tokens. At least 32 characters; the API refuses to start otherwise. Generate with `openssl rand -hex 32`. On AWS generated by Secrets Manager |
| `CORS_ORIGINS` | — | Comma-separated browser origins allowed to call the API, e.g. `https://admin.example.com`. Exact origins, no trailing slash. Empty in production = every browser origin refused (the app still works: it sends no `Origin`). Empty in development = all allowed |
| `DB_SYNC` | — | `true` creates missing tables/columns at start-up in production (always on in development). See [schema changes](../architecture/data-model.md#schema-changes) |

### Database

| Variable | Default | Description |
|---|---|---|
| `DATABASE_URL` 🔒 | — | PostgreSQL connection string. Takes precedence over the `DB_*` values. A `sslmode=…` parameter enables TLS |
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` 🔒 | port `5432` | Separate connection values (used on AWS, password from Secrets Manager) |
| `DATABASE_SSL` | `false` | `true` for hosted databases reached over the internet (Neon, Supabase, Render external URL) |
| `DATABASE_SSL_CA` | — | PEM bundle used to verify the server certificate. The Docker image ships Amazon RDS's bundle at `/app/certs/rds-global-bundle.pem` |
| `DATABASE_SSL_REJECT_UNAUTHORIZED` | `true` | `false` only for providers whose certificate Node cannot verify |
| `TEST_DATABASE_URL` 🔒 | — | Disposable database for `npm test`. **Integration tests drop every table in it.** Tests never use `DATABASE_URL` |

### Public URLs

| Variable | Default | Description |
|---|---|---|
| `API_HOST` | request `Host` header | Host used in photo URLs (`<protocol>://<host>/uploads/<name>`). Set it for a custom API domain or when a proxy rewrites `Host` |
| `API_PROTOCOL` | request protocol | `https` in production |
| `PUBLIC_API_URL` | request host | Base of the Google redirect URI `<PUBLIC_API_URL>/api/auth/google/callback` |
| `ADMIN_URL` | first `CORS_ORIGINS` entry | Where staff return after Google sign-in (`<ADMIN_URL>/login?google_code=…`) |
| `APP_REDIRECT_URI` | `civicfix://auth` | Where the app returns after Google sign-in |

### Sessions and limits

| Variable | Default | Description |
|---|---|---|
| `ACCESS_TOKEN_TTL` | `15m` | Access-token lifetime (`jsonwebtoken` syntax: `30s`, `15m`, `1h`) |
| `REFRESH_TOKEN_DAYS` | `30` | Days a session lasts without use |
| `RATE_LIMIT_MAX` | `300` | Requests per minute per IP, all endpoints. Staff behind one office connection share an IP |
| `AUTH_RATE_LIMIT_MAX` | `30` | Requests per minute per IP on sign-in, refresh, code and reset endpoints |

### Sign-in providers

All optional; each is off until configured. Setup: [Sign-in providers](../deployment/sign-in-providers.md).

| Variable | Default | Description |
|---|---|---|
| `EMAIL_PROVIDER` | `log` outside production, off in production | `ses` sends password-reset codes through Amazon SES; `log` prints them to the API log |
| `EMAIL_FROM` | — | SES-verified sender address. Required with `ses` |
| `SMS_PROVIDER` | `log` outside production, off in production | `sns` sends phone sign-in codes through Amazon SNS |
| `SMS_SENDER_ID` | — | Registered sender ID (India: DLT header, e.g. `CIVFIX`) |
| `SMS_ENTITY_ID`, `SMS_TEMPLATE_ID` | — | India DLT principal entity ID and template ID |
| `AWS_REGION` | — | Region for SES and SNS. Set automatically on AWS |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` 🔒, `AWS_SESSION_TOKEN` 🔒 | — | Only outside AWS. On ECS the task role's credentials are used automatically |
| `GOOGLE_CLIENT_ID` | — | Google OAuth "Web application" client ID |
| `GOOGLE_CLIENT_SECRET` 🔒 | — | Its secret. On AWS injected from Secrets Manager |

### Other

| Variable | Default | Description |
|---|---|---|
| `GEOCODING_ENABLED` | `true` | `false` skips the Nominatim reverse-geocoding call and stores `Location (lat, lon)` |
| `STAFF_PASSWORD` 🔒 | random | Only for `npm run create-staff`: use this password (12+ characters) instead of a generated one |

### Test only

Never set these in production.

| Variable | Description |
|---|---|
| `TEST_OTP_PHONE`, `TEST_OTP_CODE` | One phone number that always receives this fixed SMS code (end-to-end tests) |
| `GOOGLE_AUTH_URL`, `GOOGLE_TOKEN_URL`, `GOOGLE_JWKS_URL`, `GOOGLE_ISSUERS` | Point Google sign-in at a fake identity provider (integration tests) |

## Admin portal

| Variable | Example | Description |
|---|---|---|
| `VITE_API_URL` | `https://api.example.com/api` | API base URL **including `/api`**, built into the static files. Production builds fail if it is missing or is not a full URL ending in `/api` |

Anything in a `VITE_*` variable is public: it is readable in the browser.

## Android app

| Variable | Example | Description |
|---|---|---|
| `EXPO_PUBLIC_API_URL` | `https://api.example.com` | API root **without `/api`**. Optional: without it the app asks for the server on first launch |
| `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY` | — | Optional Android Maps SDK key; restrict it to package `com.civicfix.app` and the signing certificate's SHA-256. Without it the report screen shows coordinates and an "Open in Maps" link |
| `ANDROID_VERSION_CODE` | `42` | Build number; must increase for every APK. The workflow uses the GitHub run number |

Anything in an `EXPO_PUBLIC_*` variable is readable by anyone with the APK.

## GitHub Actions

### Repository variables

| Variable | Used by | Description |
|---|---|---|
| `AWS_DEPLOY_ROLE_ARN` | Deploy to AWS, AWS admin task | `DeployRoleArn` output of the `civicfix-bootstrap` stack. Without it the deploy is skipped |
| `AWS_REGION` | Deploy, admin task | Default `ap-south-1` |
| `DB_INSTANCE_CLASS` | Deploy | Default `db.t4g.micro` |
| `DB_BACKUP_DAYS` | Deploy | Automated backup retention, default `7` (free-tier accounts may need `1`) |
| `EMAIL_FROM` | Deploy | Enables "Forgot password" (SES) |
| `ENABLE_SMS` | Deploy | `true` enables phone sign-in (SNS) |
| `SMS_SENDER_ID`, `SMS_ENTITY_ID`, `SMS_TEMPLATE_ID` | Deploy | DLT values for Indian SMS |
| `GOOGLE_CLIENT_ID` | Deploy | Enables Google sign-in together with the next one |
| `GOOGLE_CLIENT_SECRET_ARN` | Deploy | ARN of a Secrets Manager secret named `civicfix/…` holding the Google client secret |
| `MOBILE_API_URL` | Android APK | Server address built into APKs from tag builds |

### Repository secrets

| Secret | Used by | Description |
|---|---|---|
| `ANDROID_KEYSTORE_BASE64` 🔒 | Android APK | Release keystore, base64-encoded. Required to publish |
| `ANDROID_KEYSTORE_PASSWORD` 🔒 | Android APK | Keystore password |
| `ANDROID_KEY_ALIAS` | Android APK | Key alias (`civicfix`) |
| `ANDROID_KEY_PASSWORD` 🔒 | Android APK | Key password |
| `GOOGLE_MAPS_API_KEY` | Android APK | Optional; becomes `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY` |

No AWS keys are stored in GitHub: workflows sign in to AWS through OpenID Connect.

## Secret handling rules

- `.env` files, keystores and certificates are ignored by Git (`.gitignore`); keep it that way.
- Use a different `JWT_SECRET` and database for every environment.
- On AWS, secrets are created and read inside AWS (Secrets Manager); the deploy logs never contain them.
- If a secret leaks: rotate it immediately ([Incident response](../operations/incident-response.md#leaked-secret)).
- Rotating `JWT_SECRET` signs everyone out of their current access token; apps renew silently with their refresh tokens.

## Pre-release checklist

- [ ] `JWT_SECRET` is random, 32+ characters, unique to this environment
- [ ] `NODE_ENV=production`, `API_PROTOCOL=https`
- [ ] `CORS_ORIGINS` lists only the real admin portal origin(s)
- [ ] The database is the intended one and TLS is on
- [ ] `VITE_API_URL` / `EXPO_PUBLIC_API_URL` point at the production API, not a LAN address
- [ ] No `TEST_*` variables are set
